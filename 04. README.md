Multi-page personal website (6 pages): Designer, Video Editor & Social
Media Manager. Founder of QuickShoppingNow and LUXAUR.

Repo: https://github.com/mehedihallmubin/personal-website

## Design

Red glass, interim design (Nov 2026). Vantablack background `#000000`,
blood red `#8B0000` glow (5-10%), crimson `#DC143C` highlight (2%),
glass cards with 16px backdrop blur, white text. Home uses the Option A
layout Sir picked (2026-11-23): hero with "Hello, I'm", big name, red
role ribbon, one stats line (5+ years personal / 2+ years working
experience), Let's Talk + View My Work buttons, his real portrait in a
glass frame with a red ring behind it; About with bio + a QuickShoppingNow / LUXAUR
brand card, then 6 skill cards with red line icons and a red bottom
glow. The header keeps the hamburger drawer + search (all 6 pages stay
reachable) — the mockup's inline nav row was not used. Phone hero
(2026-11-23, his word "Amar picture side a Hobe phoneo eitar moto"):
the portrait sits on the SIDE (right) next to the text on phone too,
like the desktop — never centered on top. Galaxy S24 / 2K (2026-11-23):
viewport meta is width=device-width; layout verified at 360px (S24) and
412px (S24+/Ultra, 1440x3120) with no sideways scroll; portrait upscaled
to 500x565 so it stays sharp on high-density 2K screens.

## Pages

- **Home** (`index.html`): Option A hero (greeting, name, red role
  ribbon, stats line, Let's Talk + View My Work, portrait with red
  ring) + About (bio, QuickShoppingNow / LUXAUR brand card, 6 skill
  cards). Short on purpose — only the important identity stays here.
- **Work** (`work.html`): Experience (roles + education timeline) and
  Services (the 6 services).
- **Portfolio** (`portfolio.html`): the 4 work samples + the 9 real
  brands with his real role at each. Admin can add/edit/remove brands
  (real ones only). No invented brands, no invented logos, no fake
  claims.
- **Reviews** (`reviews.html`): the full review system on its own page.
  Same localStorage settings as Home, so a review added on either page
  shows on both.
- **Contact** (`contact.html`): mail link + Connect (26 platforms) +
  Community (4 groups — Discord, WhatsApp Group, Telegram, Facebook
  Group — each with a Join button). Until he pastes the real invite
  link in Admin, the button opens the platform's own site; a saved
  invite gets a red border. Links are saved in Admin ("Community
  links"), per device in localStorage (key: `pw_community_links`). No
  invite link is ever invented.
- **Blog** (`blog.html`): posts added in Admin render here (newest
  first); honest empty state with no posts. He adds real posts in
  Admin.

The header, drawer, search overlay, footer and admin panel are the same
on every page. Each page file is a complete HTML file, so the header and
footer markup is duplicated across the 6 files - a header change touches
all 6 files.

## How to view it

Open any page file in a browser (`01. index.html` for Home,
`07. blog.html` for Blog, and so on). Each loads `02. styles.css`,
`03. reviews.js`, `05. social.js` and `06. header.js` from the same folder.

The assembled single-file pages (`Mehedi-H-All-Mubin-Personal-Website.html`
for Home, plus `blog.html`, `portfolio.html`, `brands.html`, `services.html`,
`contact.html`, `reviews.html`) are the same pages with the CSS and JS
inlined. The Home file in the Drive "Project" folder is the main file and
the preview. Note: the single files reference `mehedi-portrait.jpg` by
relative path, so the hero photo only shows when the image file sits next
to it (as on the live site).

## Header

- Floating glass pill (sticky, top 16px): left — hamburger menu icon
  (three lines, morphs into an X when open) + brand; right — search
  icon, mail icon, Get in Touch button (button hidden on phones).
- Hamburger opens a slide-in glass drawer from the left with all 6
  pages (Home, Work, Portfolio, Reviews, Contact, Blog) plus the email
  at the bottom. The current page is highlighted in crimson. Closes on
  link tap, close button, backdrop tap, or Escape. The hamburger is the
  only navigation on all screen sizes — no inline link row.
- Search icon opens a search overlay that searches this site's own
  content across ALL pages (sections, services, projects, brands,
  communities, platforms). A result on another page jumps to that page.
  Live results as you type; Enter or tap jumps to the result; arrow
  keys move between results; "/" opens search; Escape closes. Empty
  query lists all 8 destinations (the 6 pages + Connect + Community);
  no match shows an honest "Nothing found" message.
- Keyboard: visible crimson focus rings, focus moves into the open
  drawer/search and back to the button on close, Tab wraps inside the
  open panel.

## Review system

- Main source: Google Business Profile reviews, shown through a widget.
- "Give a Review" opens the Google review link (set in Admin). Without a link it explains that the link is not connected yet.
- Admin panel: discreet "Admin" link in the footer. It holds the Google review link and the widget embed code (Elfsight free: 200 views/month; EmbedSocial free: Google 1 source, 500 views/month). Paste the widget code and reviews appear automatically; new Google reviews update by themselves.
- Manual reviews (fallback): add a real review from the admin panel (name, stars, text). Only real reviews - never fake ones. The average rating is computed from real manual reviews only; with no reviews the section shows an honest empty state.
- Settings are stored in localStorage on the visitor's own device (keys: `pw_review_link`, `pw_review_widget`, `pw_manual_reviews`). No password on the admin panel - it is discreet, not locked.

## Admin panel

- Discreet "Admin" link in the footer. No password. Settings save in
  localStorage on the visitor's own device (per device, per browser).
- **Honest limit (shown at the top of the panel):** changes save on
  this device only. Visitors won't see them until Rio publishes them
  live — ask Rio in the Personal Website chat. No GitHub token or
  password is stored in the site's code. Anyone can open Admin on their
  own device, but their changes stay on their device and never touch
  his device or the live site.
- **Reviews:** Google review link + widget embed code + manual reviews
  (real reviews only). Same as before.
- **Social links:** profile URL for each of the 26 Connect platforms.
- **Community links:** invite/join link for Discord, WhatsApp Group,
  Telegram, Facebook Group.
- **Blog posts:** add / edit / delete posts (real posts only). Posts
  render on the Blog page (newest first); with no posts the honest
  empty state shows. Delete is two-tap (tap again to confirm).
- **Brands:** add / edit / remove brands (real brands only). The 9
  real brands are the default; a new brand's monogram is derived from
  its name. The Brands page re-renders from the saved list. Note: the
  static cards in `09. brands.html` and the defaults in
  `14. brands.js` must stay in sync.
- **Texts:** Hero (greeting, roles line), Services (6 titles +
  6 texts), Experience (7 titles + 7 texts) — 28 fields. Only values
  that differ from the original are stored; "Reset all to original"
  clears them. The roles line keeps its bold styling (rebuilt from the
  slash-separated parts, comma style with & before the last).
- **Admin (hidden):** no Admin button shows on the public site (2026-11-23, his word "Admin panel public view a thakbe na"). Open it only from a `#admin` link — e.g. `https://mehedihallmubin.github.io/personal-website/#admin` (bookmark it) — on any page; closing clears the `#admin` so a reload does not reopen it. The panel itself (blog, social, brands, reviews, community, texts) still lives in every page, hidden until `#admin`. Changes save on this device only.

## Rebuild the pages

Run the build script (it inlines 02, 03, 05, 06, 13, 14, 15 and 16 into every page file):

    python3 00. build.py

It writes the 7 assembled single-file pages in this folder and stages
copies: Home to `../files/` (the Drive main file) and to
`../github-pages/index.html`; the other pages to
`../github-pages/<name>.html`. A single page only:

    python3 00. build.py blog.html

What the script does, step by step, for each page:

1. Takes the page file (`01. index.html`, `07. blog.html`, ...).
2. Replaces the `<link rel="stylesheet" href="02. styles.css">` line with `<style>` + the full contents of `02. styles.css` + `</style>`.
3. Replaces the `<script src="03. reviews.js"></script>` line with `<script>` + the full contents of `03. reviews.js` + `</script>`.
4. Replaces the `<script src="05. social.js"></script>` line with `<script>` + the full contents of `05. social.js` + `</script>`.
5. Replaces the `<script src="06. header.js"></script>` line with `<script>` + the full contents of `06. header.js` + `</script>`.
6. Replaces the `<script src="13. community.js"></script>` line with `<script>` + the full contents of `13. community.js` + `</script>`.
7. Replaces the `<script src="14. brands.js"></script>` line with `<script>` + the full contents of `14. brands.js` + `</script>`.
8. Replaces the `<script src="15. blog.js"></script>` line with `<script>` + the full contents of `15. blog.js` + `</script>`.
9. Replaces the `<script src="16. texts.js"></script>` line with `<script>` + the full contents of `16. texts.js` + `</script>`.

Script order in the page (matters): 03, 05, 14, 15, 16 render and apply
first, then 06 builds the search index from the final page, then 13.

## Rules

- Everything real: no fake reviews, ratings, counts, handles or profile links anywhere.
- Community: no invite link is ever invented — a Join button opens the platform's own site until he pastes the real invite in Admin.
- Blog: only real posts, written in Admin. Never write fake posts.
- Brands: only real brands. Never invent a brand, a logo or a role.
- Admin changes save on this device only — they go live only when Rio publishes the repo. Never store a GitHub token or password in the site's code.
- LinkedIn appears only in the Connect section (his 2026-11-22 order); no LinkedIn icon row anywhere else.
- Portfolio stays the last section on Home.
- Header/footer markup is duplicated across the 7 page files - a header change touches all of them.
- All code, comments and docs in English.
